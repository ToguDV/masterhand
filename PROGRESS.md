## Changelog

- **2026-10-09** — **Goal Mode review polish: internal sessions hidden, marker cards in the thread and consistent controls (web + mobile).** Follow-up to the `/goal` batch after a maintainer review. (1) The critic/judge sessions no longer appear in the sidebar: the pinned opencode (v2.0.6) silently drops `parentID` on session create (verified in its schema — upstream added the field only later), so they were created as roots. The BFF now writes a stable `masterhand.goal.internal` role marker next to the unique reconciliation marker, annotates the workspace session list (`goalRole`, falling back to the run store and the legacy `masterhand.goal.role` prefix), and `rootSessions` filters the annotation, so internal sessions stay out of every client's list. Deleting the main session (`forget`) and starting a new run remove the old internal sessions explicitly — nothing cascades upstream — and the internal create reconciliation stopped filtering by `parentID` (which would never find a root session, so a lost create response replayed and duplicated it): it looks the marker up by directory instead (reproduced red: two critic sessions for one landed timeout; green after). (2) The agents' custom protocol is now used for rendering, not just orchestration: `client-core` gained a tolerant `splitGoalMarkers` parser (prose stays markdown; `<masterhand:goal|critique|verdict>` become report/critique/verdict cards, and a still-streaming tag tail is hidden instead of flashing raw JSON) plus `goalReviewRounds`/`goalActivityLabel`. (3) Each session's thread renders a **Goal review** section (web `GoalCards.tsx`, mobile `GoalReview.tsx`) with the per-round critic argument + issues and judge decision + required changes; the latest round is open, older ones expand on demand. E2E: the mock now drops `parentID` on create exactly like the pinned server (reproduced the leak: "Goal critic" listed — red before, hidden after) and `goal.spec.ts` asserts the sidebar stays clean, the raw marker is never shown and the review cards carry the round history. Verified: typecheck, coverage gate (374 server + 414 client-core + 260 mobile), full E2E and build green. - **2026-10-09** — **Goal Mode (`/goal`) + a shared, marker-reconciled opencode retry engine (#129, #130).** `/goal <goal>` on web and mobile starts a BFF-orchestrated adversarial loop around the session: the main agent works the goal until it claims completion with a `<masterhand:goal status="complete">…</masterhand:goal>` marker, an internal **critic** (child session in the same directory, allowed to inspect the workspace and run checks) challenges the claim with `<masterhand:critique>…</masterhand:critique>`, and an impartial **judge** decides with `<masterhand:verdict>…</masterhand:verdict>`; on rejection the judge's required changes go back to the main agent and the round advances, and at the round cap (default 5, configurable, resumable with a fresh budget) the run **pauses** with the last verdict. State is durable (`goal_runs`/`goal_settings` in SQLite) and every transition is a synthetic `goal.updated` frame on the existing SSE relay — clients never poll; they render a subtle strip above the composer (phase, `round N/M`, live retry notes, pause/resume/cancel/retry, expandable history) and Settings > **Goal review** picks the critic/judge models (empty = session model) and the round budget. Reliability is the point: one shared retry engine (`apps/server/src/retry.ts`, ADR-32) fronts every BFF → opencode call — idempotent methods retry transient failures (429/5xx/network) with incremental backoff, and non-idempotent writes (internal session create, every prompt, delivery-marked client prompts through the proxy) replay only after proving via a persisted marker that they did not land, so a rate limit can neither stick a turn nor duplicate it; the loop retries a failed phase up to 3 times (2s/4s/8s), nudges a missing completion marker exactly once, reconciles lost `session.idle` events with a watchdog (and on reconnect), turns in-flight runs into `paused` after a BFF restart (never auto-resumes), serializes concurrent starts (rule 12) and removes critic/judge sessions on cancel. Verified: 364 server tests (state machine, retry/reconciliation, routes, real-adapter + SSE integration), 401 `client-core`, 258 mobile, 82 E2E (new `goal.spec.ts`: rejection round → approval, transient 429 retries, cancel, cap pause + resume, empty-goal hint, settings persistence); coverage and build gates green. Docs: `docs/bff/api.md` §Goal Mode, `ARCHITECTURE.md` ADR-32/33 + §4.10/4.11 (and the duplicated syntax-highlighting ADR renumbered to 31), `docs/past-mistakes.md` rules 4/checklist/patterns.
