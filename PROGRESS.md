## Review follow-ups

Code review of PR #24 (opencode v2 migration) and PR #25 (catalog recovery) on
2026-10-01. Full findings, evidence, fix approach and tests to add:
[`docs/reviews/2026-10-01-pr-24-25-code-review.md`](docs/reviews/2026-10-01-pr-24-25-code-review.md).

- [x] **F24-1 (high):** streamed deltas and projected snapshots use different chat-part IDs (`chat.ts`), so a history refetch mid-stream duplicates or segments assistant text. Fixed 2026-10-01: projection and events now share the per-kind ordinal id and `mergeLiveMessages` preserves live text across a mid-step refetch.
- [x] **F24-2 (medium):** full-history refetch with a silent 10k cap that drops the newest messages (`client.ts`); the BFF aggregates up to 50 pages per directory listing (`app.ts`). Fixed 2026-10-01: the client pages newest-first (`order=desc`, reversed to chronological) and the BFF caches the per-directory aggregation for 5 s (cleared on mutations).
- [x] **F24-3 (medium):** the E2E mock never delivers `server.connected`, so the reconnect recovery has no E2E coverage (`e2e/mock-opencode.ts`). Fixed 2026-10-01: the mock registers the client before emitting and gained offline/online control routes; `reconnect.spec.ts` proves the catalogs repopulate after an upstream reconnection.
- [x] **F24-4 (medium):** stale pending permissions are never removed on reconnect (web/mobile `App.tsx`). Fixed 2026-10-01 with `reconcilePermissions`: covered directories are authoritative from the server snapshot, and `server.connected` now also reconciles (F25-3).
- [x] All findings closed: every high/medium/low is fixed; F24-13, F25-2 and F25-6 are intentionally left open (reasoning recorded in the review document).
